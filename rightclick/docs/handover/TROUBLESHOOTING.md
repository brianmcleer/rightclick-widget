# Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `rightclick is duplicated` when the client starts | A second copy of the widget is registered: a nested `rightclick\rightclick` folder, a leftover copy under another name, or a stale build in `client\dist\widgets`. | Keep one copy with `manifest.json` directly inside `widgets\rightclick`. Stop the client, delete `client\dist\widgets\rightclick`, start again. |
| Settings panel is blank in the builder | Something under `src/setting` (or a file it imports) imports `esri/*`. The builder has no map, and the import fails the settings bundle silently. | Remove the import. Use `loadArcGISJSAPIModules` at click time if the SDK is really needed. `tests/source.test.cjs` catches the static case. |
| Widget never loads; console shows `scriptError` for an `esri/...` file | A Maps SDK module path that does not exist in this SDK version. | Fix the import path against the SDK reference for the client's version. |
| "Cannot convert undefined or null to object" after a full rebuild | `tsconfig.json` in the widget folder was changed to classic `jsx: "react"`. ts-loader reads that file. | It must stay `jsx: "react-jsx"` with `jsxImportSource: "@emotion/react"`. |
| Visual Studio shows thousands of errors, or errors in `jimu-core` files | VS opened the `client` folder, or the widget tsconfig gained a `paths` entry. | Open only the widget folder. Keep the tsconfig free of `paths` and `baseUrl`. Close VS, delete the widget's `.vs` folder, reopen. |
| Other widgets get type errors after installing from a clone | The editor shims (`src/*-shims.d.ts`) are ambient and leak across `your-extensions`. | Delete the shim files in the installed copy, or install from the release zip, which leaves them out. |
| Nothing happens on right click | The widget is not connected to a map widget, or another widget consumes the pointer event first. | Pick the map in the widget settings. Check the console for errors from the widget on load. |
| An imported coordinate system row shows "Calculating..." and then disappears | The projection for that system failed for the clicked point: outside the system's area, or the Maps SDK rejected the definition. | Right click inside the area. If it never appears anywhere, re-import the `.prj`; check the text is complete. |
| Imported coordinates are off by about a meter | The definition's datum differs from the map's, and the default datum transformation was applied. | If the organization treats the two datums as the same, edit the `GEOGCS` part of the `.prj` to match the map's datum and import it again. |
| Imported coordinates are far off | Wrong file, or the coordinate order setting is reversed (Easting, Northing versus Northing, Easting). | Check the order in settings. Right click the system's origin: it should read the false easting and false northing. |
| The address never appears in the menu header | The reverse geocode service did not answer, or `reverseGeocodeUrl` is empty or wrong. | Test the service URL in a browser. Coordinates keep working without it. |
| Copy does nothing | The browser blocked clipboard access (no HTTPS, or a permissions policy). | The widget falls back to a small box with the text to copy by hand. Serve the app over HTTPS. |
| Measure Distance or Measure Area shows "The measuring tool could not be loaded" | The Maps SDK measurement modules failed to load. | Reload. If it persists after an Experience Builder upgrade, see "Move to a new Experience Builder version" in `MAINTENANCE.md`. |
| What's Here popup has no colors or looks unstyled | The popup content sits in a shadow root that the page stylesheet cannot reach, and the embedded style was stripped. | `applyRcWhInlineStyles` is the fallback and runs on every render of the content; check the console for errors thrown before it. |
| What's Here lists nothing for a layer that is on | The layer is out of range at this zoom (its own scale range or a group's above it), is hidden from the layer list (`listMode: hide`), cannot be queried (tile, vector tile, imagery), its filter excludes the features, or it is unticked under What's Here layer selection. | Zoom in until it draws; check the layer tree in settings. A layer added at runtime is searched automatically unless a group above it is unticked. |
| What's Here still uses an old list of layers after an upgrade | The app was saved with the pre-2.4.0 include list. | Open the widget settings once (it converts the list and shows a note), then save the app. |
| A custom action row is missing | Feature rows only appear when a matching feature is under the click and its layer is on and drawing. | Turn the layer on, zoom in, right click the feature. Check the row's layer title or URL match text. |
| Property Report or Mailing Labels opens but ignores the clicked point | The target widget did not read the handed-over point, or the container setting does not match the app layout. | Check the target widget id and the container type (controller, accordion, nested) in settings. |
| New strings show in English in another language | The locale files have not been regenerated since the string was added. | Run the exb-i18n-kit sync, then publish. |
| A release zip contains scratch files | It was zipped from the live Experience Builder folder. | Always release through `publish.ps1`, which builds the zip from a cleaned staging copy. |
