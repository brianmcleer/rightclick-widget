# Maintenance

Routine jobs and where to make each change. After any of them, run the two checks in
`README.md` (`npx tsc -p .` and `node --test "tests/*.test.cjs"`).

## Add a built-in menu row

1. `src/config.ts`: add the switch to `enabledActions` in `IMConfig`.
2. `config.json`: add its default.
3. `src/runtime/translations/default.ts`: add the row label.
4. `src/runtime/widget.tsx`, `getMenuItems()`: push the row (`action`, Calcite `icon`, `text`, `group`).
5. `handleContextMenuAction()`: add the `case` for the action.
6. `src/setting/setting.tsx` and `src/setting/translations/default.ts`: the switch and its label.
7. Help guide: add a flag to `HelpFeatures` in `src/runtime/helpSections.ts`, compute it in
   `helpFeatures` in `widget.tsx` from the same check `getMenuItems()` uses, and add a
   `helpMenu*` line. Add the flag to `BOOLEAN_FLAGS` and the gating cases in
   `tests/helpGuide.test.cjs`.

## Add a setting

1. Type and default in `src/config.ts`; default value in `config.json` when it should be
   visible to a new widget.
2. Control in `setting.tsx`, label in `src/setting/translations/default.ts`.
3. Read it in `widget.tsx` once, near where it is used. A switch that turns a feature off
   must remove the menu row, the help line and the runtime work.
4. Nothing else is needed for the XML export: it serializes the whole config.

## Add or change a string

- Runtime strings: `src/runtime/translations/default.ts`. Settings strings:
  `src/setting/translations/default.ts`. One key per line.
- In React code use `t('key')`. Outside the component tree (HTML builders, helpers) use
  `__t("key")`. Values go in as `{name}` tokens: `t('copiedValue', { value })`.
- Text that goes into popup HTML must pass through `escapePopupHtml(...)`.
- No em dashes; plain words.
- The other 39 locales are generated by exb-i18n-kit. A new or changed English string
  shows in English there until the next `exb-i18n sync`.

## Add a help guide line

Edit `src/runtime/helpSections.ts` and the `help*` keys. Rules (playbook Section 10.8):
name buttons exactly as the menu shows them, one idea per line, troubleshooting lines
read "Symptom: cause. What to do.", the contact line stays last. The tests enforce these.
Do not edit `HelpPopup.tsx`; it is shared.

## Colors and components

- React UI: `const tokens = useTokens()` and read `tokens.*`.
- HTML built for the Maps SDK (What's Here popup, measurement panels): read `rcPalette.*`.
  It is refreshed from the theme on every render.
- The only color literals allowed in `widget.tsx` are the `rcPalette` defaults and the
  default colors of graphics drawn on the map. A test checks this.

## What's Here layers

- The rule for which layers are searched lives in one place,
  `src/runtime/lib/layerWalk.ts` (`collectQueryableLayers`). Change it there and add a
  case to `tests/layerWalk.test.cjs`; What's Here and feature-scoped custom actions both
  follow it.
- Nothing is cached. If What's Here ever looks stale, look for a closure that froze
  config or a layer reference, not for a cache. Config is read through
  `latestConfigRef`.
- The layer selection stores the layers to leave out (`mode: 'excluded'`). Keep it that
  way: an include list freezes What's Here to the layers that existed when it was saved.

## Imported coordinate systems

- The settings panel only checks the WKT text for structure (`parseWktInfo`); it must not
  import `esri/*`. The runtime builds the `SpatialReference` and projects.
- A definition is used exactly as written. Datum handling is described in the widget
  README under "Imported coordinate systems".
- To check a system, right click its origin: the row should read the false easting and
  false northing from the file.

## Move to a new Experience Builder version

1. Bump `exbVersion` in `manifest.json`, and `$ExbWidgetPath` in the repository's `publish.ps1`.
2. Check every `esri/*` import path against that version's Maps SDK reference. A wrong
   path fails the whole bundle at load.
3. Confirm the `arcgis-distance-measurement-2d` and `arcgis-area-measurement-2d`
   components still register through `import 'arcgis-map-components'` and that their
   `unitOptions` and `hideStartButton` properties still exist (2.3.0).
4. Re-copy `src/exb-editor-shims.d.ts` from the family master if it changed.
5. Run the checks and the browser smoke test. Record what changed in a new
   `docs/PORTING_<version>.md`.

## What the tests cover

| Suite | Covers |
|---|---|
| `tests/wkt.test.cjs` | `.prj` / WKT recognition, with the Mesa County file as a fixture. |
| `tests/config.test.cjs` | Layer matching for custom actions, layer selection keys, defaults. |
| `tests/helpGuide.test.cjs` | Help guide content, feature gating both ways, writing rules. |
| `tests/layerWalk.test.cjs` | Which layers What's Here searches: visibility up the tree, inherited groups, sublayers, scale ranges, layer view state, subtype groups, order, the change signature, the layer selection rules, and the point query. |
| `tests/source.test.cjs` | Every used translation key exists; no dashes or emoji in strings; no Maps SDK import in settings; no dynamic import; no undeclared dependency; no hard-coded UI colors; versions agree. |

They do not cover React rendering, the Maps SDK, projection results or the popup in a
browser. Those need the smoke test.
